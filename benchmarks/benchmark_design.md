# Benchmark 方法設計及實驗控制
## 1. 目標

此 Benchmark 評估分類模型在邊緣設備上的真實推論延遲。

測量目標包括：
- 系統層級冷啟動延遲
- 程序層級冷啟動延遲
- 穩態推論延遲
- 記憶體使用行為

## 2. 測試環境
- 設備：Raspberry Pi 5 / Jetson Nano 2GB
- 作業系統：基於 Ubuntu 的 Linux
- 模式：CLI（multi-user.target）及 Desktop (graphical.target)
- Python：隔離的虛擬環境
- 模型：`pet_classifier_fp32.tflite`,  `fp32.trt`, etc.
- 輸入：確定性影像清單（list.json）
- 使用使用 Python time.perf_counter()記錄時間

所有設備使用相同的影像順序以確保公平性。

## 3. 基準測試階段
### 3.1 重啟冷啟動

定義：
> 完整系統重啟後的第一次推論（CLI 模式 / Desktop 模式）。

目的：
- 測量完整系統初始化的額外開銷
- 包含核心、驅動程式與執行環境初始化成本

步驟：
1. 開機進入 CLI（無 GUI）/ Desktop (有 GUI)
2. 記錄系統資訊
3. 執行一次推論
4. 記錄延遲

### 3.2 程序冷啟動

定義：
> 清除作業系統頁面快取後的第一次推論

目的：
- 測量執行環境層級的冷啟動成本
- 排除完整系統重啟的影響

步驟：

每次執行：
1. 清除頁面快取 (僅 CLI 模式，Desktop 未做清除動作)
2. 記錄記憶體狀態
3. 執行一次推論
4. 記錄延遲

重複 10 次。

### 3.3 穩態

定義：
> 預熱後的持續推論。

目的：
- 測量穩定化後的推論延遲
- 評估執行環境的一致性

步驟：
1. 執行一次預熱（不記錄）
2. 執行 30 次推論迭代
3. 記錄每次延遲
4. 計算平均值、中位數、標準差、最小值、最大值

## 4. 記憶體記錄

記憶體記錄方式：`free -m`

捕捉時機：
- 推論前
- 推論後

記憶體記錄在 bash 層級進行，以避免干擾計時。

## 5. 可重現性
為確保可重現性：
- 使用相同模型檔案
- 使用相同影像順序（list.json）
- 使用相同虛擬環境
- 使用相同批次大小
- 使用相同推論腳本

## 6. 輸出
每個模型生成專屬的 CSV 檔案：`<model_name>_benchmark.csv`

格式：
`mode, latency_ms`

模式包括：
- reboot_cold
- process_cold
- steady

## 7. 限制
- drop_caches 僅影響 OS page cache，無法清除 GPU driver 或 CUDA context 狀態。
- 結果可能因背景程序而有所不同
- 所有測試於室溫環境下進行，設備未額外加裝散熱模組
